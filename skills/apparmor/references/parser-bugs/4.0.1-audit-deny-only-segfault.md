# `apparmor_parser` 4.0.1 — a profile whose only file rules are `audit deny` crashes the parser

**Observed on:** a distro build of parser 4.0.1 (Ubuntu 24.04 family, package version `…really4.0.1…`). Not checked on stock Ubuntu, on other versions, or upstream; no upstream report found (searched 2026-10).
**Fixed in:** unknown.

## The bug

If every file rule in a profile is an `audit deny` (no file allow, no plain `deny`), the compiler segfaults when it builds policy for a kernel that advertises `policy/diff_encode` (`/sys/kernel/security/apparmor/features/policy/diff_encode`). `apparmor_parser` prints nothing and exits **10** — `ECHILD`, its code for a compile worker killed by a signal; with `-j0` the shell shows `Segmentation fault` and exit 139 instead. The profile mode makes no difference (enforce, complain, `unconfined`, `default_allow`), and neither does the `abi`. Non-file rules (`userns,`, `network`, `capability`) don't avoid it.

```apparmor
abi <abi/4.0>,
include <tunables/global>
profile x /opt/x flags=(unconfined) {
  userns,
  audit deny @{HOME}/.ssh/{,**} rwmlk,   # only file rule -> exit 10, no message
}
```

One file allow or plain `deny` in the same profile avoids it, including one pulled in by an include (`abstractions/base`, `abstractions/private-files`). So does compiling with `apparmor_parser -O no-diff-encode`. A child profile is judged on its own rules: an audit-deny-only child crashes even if its parent has allows.

## Where it bites

- A userns stub (`flags=(unconfined)` + `userns,`) whose `local/` include holds only `audit deny` lines: the reload fails instead of loading, and the profile stays unloaded or keeps its old policy. Those denies would protect nothing anyway (`4.0.0-4.0.1-unconfined-mediation.md`).
- A minimal test profile written to try one deny.

## Detect

Read the exit code, not the output: `apparmor_parser -QTK <file>; echo $?` prints `10` with empty stderr. `strace -f -e trace=none apparmor_parser -QTK <file>` shows the compiler process `killed by SIGSEGV`.
